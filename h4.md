## a) Räpylä

Valitsin demoniksi tunnilla esiin tuodun PostgreSQL:n.

Asensin PostgreSQL:n käsin:

```
sudo apt-get update
sudo apt-get upgrade
sudo apt-get install postgresql
sudo systemctl enable --now postgresql
````
Tarkistin että palvelu käynnistyi:
````
sudo systemctl status postgresql
````
Testasin toiminnan kirjautumalla postgres-käyttäjänä:
````
sudo -u postgres psql
````
Testikomento:
````
SELECT version();
````
Tämä osoitti, että PostgreSQL toimi.

## b) Automaatti

Automatisoin PostgreSQL:n Ansiblella.

Loin roolin:
````
mkdir -p roles/postgresql/tasks
````
tasks/main.yml:
````
- apt:
    name: postgresql
    state: present
    update_cache: true

- service:
    name: postgresql
    state: started
    enabled: true
````
Lisäsin site.yml:
````
- hosts: all
  become: true
  roles:
    - postgresql
````
Ajoin:
````
ansible-playbook -i hosts.ini site.yml --ask-become-pass
````
Asennus onnistui.

## c) Asetus

Muokkasin PostgreSQL:n asetuksia masterilla muuttamalla:
````
listen_addresses = '*'
````

## d) Paikka remonttiin

Rikoin asennuksen poistamalla PostgreSQL:n:
````
sudo apt-get purge postgresql
````
Purgen jälkeen, kun lähdin ajamaan playbookia tuli erroria. 
--> _asetushakemisto oli hukassa_ -.- 
````
Destination directory /etc/postgresql/15/main does not exist
````
Korjasin roolia lisäämällä hakemiston luovan `file`-taskin ennen `copy`-taskia.

Lisäksi korjasin handlerin nimen, jotta `notify` löysi oikean handlerin.

Ajoin playbookin uudelleen...

Ansible palautti järjestelmän toimivaksi. 
_let's go_

## e) Idempotentti

Ajoin playbookin uudelleen:
````
ansible-playbook -i hosts.ini site.yml --ask-become-pass
````
(turha) huomio:
_Mainitaan nyt edes kerran tämä niin kaunis komento..._

````
changed=0
````
Tämä osoitti, että tila oli idempotentti.
